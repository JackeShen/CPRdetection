# 骨架数据提取 —— 服务器部署说明

把本文件夹（`extract_pipeline/`）整个拷到服务器即可运行，**不依赖 st-gcn 训练代码**。
流程：视频/图片序列 → YOLO26-pose 提骨架 → COCO 17 点映射成 OpenPose 18 点 → 中心化 → ST-GCN 训练数据 (npy + pkl)。

---

## 一、整体流程（一张图看懂）

```
原始视频/图片序列 (每类一文件夹)
        │
        ▼
   YOLO26-pose 逐帧检测人体关键点 (COCO 17 点)
        │
        ▼
   17 点 → 18 点映射（补 neck = 左右肩中点；眼睛/耳朵左右对调）
        │
        ▼
   坐标归一化(0~1) → 中心化(减0.5，变 -0.5~0.5)
        │
        ▼
   组织成 (N, 3, T, V, M) 张量 + (样本名, 标签) pkl
        │
        ▼
   train_data.npy / train_label.pkl / val_data.npy / val_label.pkl / label_map.json
```

**关键维度**（ST-GCN 认的格式）：
- `N` = 样本数（每个视频/图片序列 = 1 个样本）
- `C=3` = 通道 `[x, y, score]`，x/y 中心化到 -0.5~0.5，score 是 0~1 置信度
- `T` = 帧数（默认 300，多则均匀采样、少则补零）
- `V=18` = OpenPose 18 关节点（默认 layout）
- `M` = 人数（CPR 场景默认 1，只留施救者；已自动剔除躺地者）

## 二、服务器环境准备

```bash
# 1. 建议用 conda/venv 建一个干净环境（3.10/3.11 最佳；3.8 也能用，见下）
conda create -n stgcn_extract python=3.10 -y
conda activate stgcn_extract

# 2. 装依赖
pip install -r requirements.txt

# Python 3.8 可用，但需注意：
#   - requirements.txt 已锁 numpy<2（numpy 2.0 起不支持 3.8）
#   - pip 在 3.8 上会自动选到 torch 2.4.x（2.5+ 已不支持 3.8），无需手动降级
#   - ultralytics>=8.4.75 官方支持 3.8
#   若服务器只有 3.8：conda create -n stgcn_extract python=3.8 -y 即可，其余不变。

# 3.（有 GPU 的服务器）把 torch 换成对应 CUDA 版本，例如 CUDA 11.8：
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118
#   先确认 CUDA 版本：nvidia-smi
```

> 模型是 **YOLO26-pose**，必须用 `ultralytics>=8.4.75`，否则加载报错。

## 三、准备数据（输入）

把数据按「**类别文件夹**」组织好，拷到服务器：

```
mydata/
    动作A/    a1.mp4  a2.mp4 ...        # 视频
    动作A/    a1/  (里面 *.jpg)         # 或图片序列目录（SupC14 整理后就是这种）
    动作B/    b1.mp4 ...
    ...
```

- **文件夹名 = 类别**（= 标签来源）。脚本按字母排序，label = 排序索引 0..N-1
- 每个文件夹下可以是 **视频文件** 或 **图片序列子目录**（混用也行）
- 同一动作拍了多次/多视角，就放多个文件/子目录，它们标签相同，但都是独立样本

> 如果源数据是 SupC14 那种「类别/重复/视角」图片序列（如 `SupC00/SupC00_r00_ch0/*.jpg`），
> 直接保持这种两层结构即可——外层文件夹名(SupC00)就是类别，内层每个子目录是一个样本。

## 四、准备模型

把 `yolo26m-pose.pt` 拷到服务器（和脚本同目录或任意位置），用 `--model` 指定路径。
无需联网下载。

---

## 五、运行命令

```bash
# 基本（CPU）
python yolo2stgcn.py \
    --video_root ./mydata \
    --model ./yolo26m-pose.pt \
    --out ./out \
    --device cpu

# 推荐（有 GPU，CPR 单人）
python yolo2stgcn.py \
    --video_root ./mydata \
    --model ./yolo26m-pose.pt \
    --out ./out \
    --device 0 \
    --max_frame 300 \
    --num_person 1 \
    --select cpr \
    --val_ratio 0.2
```

**常用参数**：
| 参数 | 默认 | 说明 |
|---|---|---|
| `--device` | 自动 | `cpu` 或 GPU 序号 `0` |
| `--max_frame` | 300 | 每样本固定帧数 T（建议 300，供训练随机采样 150 帧窗口） |
| `--num_person` | 1 | 每帧保留人数；CPR 场景设 1（只留施救者） |
| `--select` | `cpr` | `cpr`=剔除躺地者留施救者；`top_conf`=按置信度取前 N 人 |
| `--val_ratio` | 0.2 | 验证集比例（按类别分层抽） |
| `--imgsz` | 640 | YOLO 推理尺寸 |
| `--conf` | 0.25 | 检测置信度阈值 |

进度会逐样本打印：`完成 动作A/a1 -> shape (3, 300, 18, 1)`。

---

## 六、输出（可拷回本地喂 ST-GCN 训练）

```
out/
    train_data.npy      # (N_train, 3, T, 18, 1)
    train_label.pkl     # (样本名列表, 整数标签列表)
    val_data.npy
    val_label.pkl
    label_map.json      # {类别名: 标签索引}
```

- `train_label.pkl` 是 `(names, labels)` 两个 list，靠下标和 npy 一一对应
- `label_map.json` 记录「哪个文件夹名对应数字几」，训练改 `num_class` 时用

---

## 七、注意事项 / 排错

1. **躺地者剔除是启发式规则**（基于「框宽 + 贴底位置」）。建议转完后抽查几个样本，确认每帧都选对了施救者。如果某些特殊视角误判，调 `select_cpr_person()` 函数即可。
2. **偶发空检测帧**：脚本已做「沿用上一帧」兜底，不会留下零关节空洞。
3. **`--num_person` 与 M 通道**：设 1 时输出 `M=1`，单人动作数据更干净。若想保留双人，设 2 并改 `--select top_conf`。
4. **显存不够**：减小 `--imgsz`（如 416），或单进程跑（本脚本本身就是逐样本串行）。
5. **running 时间长**：112 样本约 4.7 万帧，CPU 按小时计，GPU 快很多。可先小批量验证（挑几个类别/视角）。
6. **ultralytics 报错 "AttributeError / YOLO26"**：就是版本太低，升级 `pip install -U ultralytics`。
